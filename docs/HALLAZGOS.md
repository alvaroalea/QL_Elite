# Findings about the original that are reproduced

Moved from `CLAUDE.md` (section 8.2). Consult before porting or touching a routine.

- `tnpr` adds in **8 bits**: with 193 or more units of an item in kg/g, buying (256 − what you carry) wraps around and is accepted. `GCASH` computes the amount in **16 bits**: a sale of more than 6,553 Cr at once loses the high bits (e.g. 200 kg of platinum). They are reproduced with `TRADE_FAITHFUL 1` in `game.h`; with 0 they are corrected.
- **`PDESC`:** the original sets `NRU% = 0` and walks 256 positions from `RUPLA-1` (foreign memory; it can hang the data screen during mission 1); the port walks the 26 entries. Measured in the emulator: the result almost never changes (1 case in 200).
- **`MT17` (found while verifying, 2026-10-17):** `LDA BUF-1,X` with `BUF = $0100` assembles in zero page (`B5 FF` in the reference binary), so `VOWEL` looks at byte `DTW5 - 1` of zero page, not the last letter of the name: it almost never removes the vowel before "IAN". It is reproduced with `zp_peek` (RAND, INWK and K3; `CHPR` stores each character in `K3`).
- **`MCNT` goes down** (`DEC MCNT` in `TT100`, after `M%`); the port made it go up. It now goes down as in the original and at 0 parts 2 to 4 run; `WARP` sets `MCNT = 1` and `EV = 0`.
- **`DORND` carries:** in `DT6` it enters with C = 0 (`CMP #129`); in `MT18` the first with C = 0, the second with the first's output carry and the rest with C = 0 (`DASC` returns with `CLC`); in parts 2 to 4 each `DORND` carries the carry of the previous instruction (`encounters.c` models them one by one; the entry one comes from `M%` and is approximated by that of the last `DORND`).
- **Apple text-mode text:** `clss` (going past row 23) only moves the cursor to (0, 0) in graphics mode; in text mode the original would hang. The port always moves it.
- **`WPLS2`** needs `LSY2[0] = $FF` as a sentinel; in the original `RES2` sets it on launch (in the port, `sun_forget` and the initial value).
- `LL52` negated with `1-x` instead of `1-x-1` in the first transcription (fixed; found by verification).
- `CHECK`/`CHECK2` only detect 57 % of one-bit changes.
- **Laser (found while verifying, 2026-10-17):** `SHD` is not just "+1 without passing 255": it **falls into `DENGY`**, so charging a shield uses 1 energy. In `SPIN` the `TYA` covers the random number: the quantity of debris is `type AND byte 0 of the blueprint AND 15` (0 or 4 plates; 0, 1, 4 or 5 canisters), only with a 50 % probability. In `SFS1` the speed of the debris is the `X` left by `DORND` (random 0–15), not the type. The `DORND`s of `LASLI`, `SPIN` and `SFS1` receive carries that come from the code's own `ADC`/`CMP` (`em_rand_c` is set by hand; after `NWSHP` it is 1 if there was room).
- **Laser (original behaviour that is reproduced):** with the military laser against a Constrictor the `LSR LAS` leaves the power at 1/4 for the rest of the frame; the station takes no damage but gets angry (`AN2`: `NEWB` bit 2 of slot 1); **the bounty is not collected if there is a message on screen** (`DLY` ≠ 0) or in hyperspace (`MJ`); the destroyed ship leaves in its byte 35 whatever `A` the sound left (here 0).
- **Damage (found while verifying, 2026-10-17):** when scooping a canister the `DORND` enters with C = 1 (left by `CPX #OIL`); altitude is `SQRT(R Q)` with whatever `Q` there was before (may vary by 1–2 units); on crashing into the planet `ALTIT` stays at 255 (the `JMP DEATH` exits earlier). The `SBC` of `OOPS` has no `SEC`: the incoming carry comes from the caller (in a collision, bit 0 of the other ship's energy).
- **Damage (original behaviour that is reproduced):** colliding with a ship destroys it and gives a bounty (but does not add to `TALLY`); with shields exhausted, each hit may destroy cargo or equipment, including the fuel scoop or the energy unit; the remains of our ship in `DEATH` never collide with us (z carries bit 6). In the original `SOEXPL` (the explosion noise) calls `DORND` and consumes random numbers if sound is on; since round 16 the port does too (before it did not).
- **Planets at the edge (bug seen on the QL, fixed and verified, 2026-10-17):** `WPLS2` (erasing the planet) decides whether to copy (X2, Y2) into (X1, Y1) by looking at `SWAP`, which in the original `LOIN` leaves (0, or $FF if it swapped the endpoints). The port drew with `gfx_line`, which does not touch `SWAP`, and whatever `LL145` had set when clipping at the edge remained: with `SWAP` ≠ 0, `WPLS2` drew all the lines from the same point. Lesson: **an own primitive that replaces a routine of the original must reproduce its effects on the variables someone reads afterwards**.
- **SUN:** the `DORND` of the ragged edge receives the carry `LL5` returns with (bit 7 of the remainder); `em_ll5` is now a literal transcription that returns it in `em_carry`. `HLOIN` rounds X1 and X2 to even and, if X2 < X1, leaves X2 = X1. **`RES2` sets `LSX2` and `LSY2` to $FF**: the sentinel of `LSY2[0]` is indeed initialised by the original (on launch), it is not a bug of its own.
- **DOCKIT** looks at `K3+10` (= `XX2+10`, visibility of face 10 of the last ship drawn) to decide whether a ship has docked; it is reproduced as is (`zk3[10]`). In `DOKEY`, a hard roll by the docking computer sets `JSTX = 64` and releases the roll key even if it is pressed.
- **The bomb:** the source version relaunches the bomb (without erasing the previous bolt) if `B` is pressed while it is exploding; the published one (IB disk) prevents it and is the one followed.
- **TACTICS (when porting and verifying, 2026-10-17):** `BIT M32+1` uses as mask the operand of the `LDY #32` instruction (= $20: "exploding"); `EXNO2` after a missile hit receives the target's **slot**, not its type (and `TA352` uses `LDX #PLT`); `FRMIS` falls into `ANGRY` with the A that `SOHISS` leaves; `ANGRY` looks at `TYPE` (the ship in progress), not the type of the one being angered, to decide whether to make it hostile; any ship's ECM uses the same `ECMA` and changes our E bulb; each `DORND` of TACTICS receives the carry of the previous comparison (modelled in `em_rand_c`). In the test, sound is disabled (`DNOIZ` = $FF) so that `SOEXPL`/`SOHISS` do not consume random numbers (since round 16 the port consumes them only with sound on; in the tests `snd_dornd_hook` is not set or those sounds are not reached).
- **`DVIDT` (found while verifying Maths Geometry, 2026-10-18):** after `ASL P; ROL P+1`, the `ASL Q; LSR Q` leaves C = 0, so **bit 7 of `P+1` is lost** and the first `ROL A` shifts in a 0. The C transcription and the Python one (`ref6502b.dvidt`) shifted it in; because of that `TIS3` gave another value and `TIDY` (orthonormalising the ships' orientation) came out different in 44 % of the cases. Fixed in both.
- **`FMLTU` with A = 0 or Q = 0 does not touch the carry** (`BEQ MU3`/`MU3again` before the `CLC`): it exits with the incoming one. In `EXS1` the `EX5` branch then subtracts with C = 1 (no borrow). `em_fmltu` no longer sets `em_carry = 0` in those cases (the caller sets the incoming one).
- **Apple II `LOIN` (when verifying point by point, 2026-10-18):** the slope comes from `log`/`logL`/`alogh` (quotient with logarithms, 255 if there is no borrow), the error starts at S = 128, one dot per x (or y) and it **does not draw one of the endpoints**: in the more horizontal lines that go up, the call's (X2, Y2); in those that go down or are flat and in the more vertical ones, (X1, Y1). The carries entering `S + Q` are always 0. The Bresenham the port used (`gfx_line`) did not match in any case; now `loin_draw` (lines.c) is the transcription and ships, planets, sun, laser and bomb use it. `HLOIN` and `VLOIN` (with `CPIX`, 2 dots wide) already matched in coverage.
- **Start and end (round 21):** `RES2` does much more than the turns: `NOSTM = NOST`, `LSX2`/`LSY2` = $FF, `MSTG` = $FF, `JSTY` = 128 (**not** `JSTX`), turns and `DELTA`/`ALPHA`/`ALP1` = 3, `dontclip` = 0, `Yx2M1` = 135, `SPBLB` if there is a station (`SSPR`), `ECMOF` if the ECM is sounding, `WPSHPS`, `ZERO`, `SLSP = LS%` and it falls into `ZINF`. `RESET` = `ZERO`, `BETA..ALP2` (7 zero-page bytes: turns, `QQ22`, `ECMA`, `ALP1`) to 0, `JSTGY` = $FF, `QQ12` = $FF (docked), `FSH`/`ASH`/`ENERGY` = $FF and `RES2`. In `DFAULT`, `CHK2`, `CHK3` and `CHK` are fixed variables **outside** the copied block (84 bytes: name and `TP`..byte 75); if `CHK` or `CHK3` do not match the original repeats `CHECK` **forever** (anti-tampering) and the port returns an error; bytes 20-21 and 47-50 of the block are unused. `TT170`, `TITLE`, `BR1`, `DEATH2` and `DEATH` are own screen flow: `no-verificable` (not verifiable).
- **Moving and Equipment (round 23):** the carry `MLTU2` exits with (16 rounds of `ROR`/`ADC`) is the last bit shifted out of `ROR P` and is **always 0** (checked with 100,000 pairs); the previous formula (`(~P) AND Q AND 1`) sometimes gave 1 and threw off the ships' `INWK+3` in part 3 of `MVEIT`. `MVEIT` with a planet or sun that has bits 7 or 5 of `INWK+31` reads the blueprint at `XX0` (foreign memory): it does not occur in the game and the test does not generate it. In `EQSHP` the order is: `eq` charges (if there is no money, message and end, even if you already have it), then `pres` returns the amount if you already have it (also missile number 5), and lasers refund the old one with `refund` (POW→4, POW+128→5, Armlas→12, any other→13).
- **Dashboard and Flight (round 25):** `DIS7` calls `MSBARS` twice with the `JSR P%+3` trick (each draws Y1+1 and Y1+2), i.e. 4 `HLOIN` per bar; `DIS1+2` leaves a single `LSR` (fuel is `QQ14 >> 1`); `CPIX` starts with `STA Y1`, which is why the `VLOIN` of the radar stick uses the head's y; `cntr` looks at `auto` before `DAMP` (with the docking computer it always centres). The E bulb is at x = 56 and the S at x = 192, y = 176..183, bit 0 on the left; `ECBT`/`SPBT` are `7F 7F 07 7F 7F 07 7F 7F` and `7F 7F 07 7F 7F 70 7F 7F`. `MJP` in the IB variant repeats `GTHG` until there are 3 Thargoids and leaves `NOSTM = 2` (in the `_SOURCE_DISK_CODE_FILES` variant it is another condition). In `TT110` the station is type 2 with the Dodo blueprint if the tech level is ≥ 10. In `TT18` the `DORND` of the failed jump enters with the carry of `CMP #9` (C = 1 if a key ≥ 9 is pressed; the port assumes no key).
- **Sounds that consume random numbers:** `SOEXPL` (explosions, death), `SOHISS` and `SOBOMB` call `DORND` once per click for the delay (Y times, 256 if Y = 0; 25 in `SOBOMB`) **if sound is on** (`DNOIZ` bit 7 = 0). The port now does too (`snd_dornd_hook`, set by `ships_hooks`). In `BOMBEFF` the carry `BOMBON` enters with is 1 in the space view and, outside it, the one `SOBOMB` leaves.
- **Radar colours:** on the Apple II `CYAN` and `MAG` equal `WHITE`: the "cyan" and "magenta" ships on the radar are white. The port shows them in cyan and magenta (a presentation decision, `docs/DECISIONES.md` 9.2).
- **`DOEXP` with 6 in byte 2 of the heap** (no ship: `4 * vertices + 6`) would make `EXL1` wrap Y around (256 copies); it does not occur with the game's blueprints and the test does not generate it.
- **Apple text mode:** the text views (all except space, the title and the charts) use the 40 × 24 text page; `NLIN4` then puts dashes (`NLI4`) under the characters of row 1. The QL has no text mode: `nlin4` always draws the `y = 19` line of graphics mode.
- **Stardust (round 17):** the `DORND`s of `KILL1`/`KILL6`/`KILL2`/`ST5` receive the carry of the comparison that sends them there (`CMP #120; BCS` → 1, `CMP #16; BCC` → 0, `BEQ` → 1); `PIXEL` returns with C = 1 if ZZ ≥ 80 or if the row is not a multiple of 8 (otherwise 0) and `PIXEL2` with C = 1 if the particle is outside; the first `DORND` of `nWq` carries the incoming carry, and `nWq` falls into `WPSHPS`. The port did not model those carries (22 % of the cases gave another cloud).
- **Charts (round 17):** the galactic chart's dots are `PIXEL` with ZZ = 255, i.e. **two dots** (the port put one); the local chart also has the `NLIN4` line at y = 19; `TT16`/`TT123` move the crosshair without sticking it to any system and do not move it if it would wrap (before, the port stuck it to the nearest system and limited it to the visible part of the local chart: see `docs/DECISIONES.md` 9.3); in `TT23`, with row Y = 1 occupied, `Y - 2` = 255 reads `INWK - 1` = `SC+1` (never 0, the port treats it as occupied); `HME2` compares the name with the one `cpl` prints in the justified buffer: with `QQ17 = $C0` (the usual) it works, with `$80` it does not find system 0 (it comes out in capitals) and with 0 or `$40` none.
- **Tunnels (round 17):** in `HFL2`, each `SOHISS` enters with C = 0 (`CLC; ADC #8` or `CMP #160; BCC`); `TT110` does `LAUN` (two 256 `SOHISS` and the tunnel) **before** `RES2`/`SOS1`/`NWSPS` and then `HFS1` draws the same rings (with their sounds) again to erase them; the port now does it in that order (`tunnel_laun`, `space_launch`, `tunnel_draw`). In `LL164` the first `SBC #10` carries the incoming carry (with C = 0 the tones drop by 11 the first time).
- **Screen (round 17):** `TTX66` leaves `LSP = 0`, prints in the space view its name ("Front View" in Sentence Case, column 11, row 1) and, if there is a hyperspace countdown, the number at (1, 1); the graphic views carry `BOX` (blue line at y = 0, `HLOIN` from 0 to 255 plus the corners: dot 254 too); the blue borders `clearrow` paints (bytes 0 and 37 of each row) fall outside the game's 256 dots; `CLYNS` (jump token 21) did nothing in the port: it now clears rows 15 and 16 (y = 120..135) in the graphic views or writes 64 spaces from (1, 21) in the text ones.
- **Tools (round 17):** `PIX1` (Maths) falls into `PIXEL2`, `TT22` into `TT15`, `TT16` into `TT103`, `TT20` into `TT54`, `nWq` into `WPSHPS`, `CLYNS` into `clearrow` and `clearrow` into an `RTS` (`SCR1`): the following block has to come after. `BOX` has no header of its own (it is in the `TTX66K` block), `DTW2` is a byte of the code (without defining it, `STA DTW2` overwrote a stub) and the real `PIXEL` needs `TWOS3`, `SCTBL/H/H2` and `SCTBX1/2`. A hook set on the address of a real routine logs and lets it run.
- **Tools (round 16):** when a branch does not reach a label outside, `frag6502.build` adds a local `RTS`, **which does not imitate what is there**: `PL21` is `SEC; RTS` and with the local RTS `PLS6` returned C = 0 on overflow (the real routine had to be included). If the branch is far from the end, the local `RTS` must be placed right before the block (`TT48` in `DOEXP`). `SKIP n` is changed to `n` × `EQUB 0` (`BOMBTBX`); `EQUD %...` of `MASKT` is expanded; `DNOIZ` is a code label (without it it stayed as a stub, whose $60 byte has bit 7 = 0 = sound on). `tests/test_state` accepts the vectors file as an argument and now prints the port's value on failures.
- **Tools:** `frag6502.build` turns into stubs the `EQUW`s to outside routines (`JMTB` table); the `TT26` block also needs the `BELL` one (the `EQUB $2C` of `DA7` jumps to its `LDA #7`). `elitesrc.py` did not evaluate `INT(...)` (`Armlas` stayed undefined and the assembler turned it into a stub); fixed.
