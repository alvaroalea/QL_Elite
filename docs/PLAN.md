# Elite QL - port plan (disk version, up to 640 KB)

Reference: https://elite.bbcelite.com/apple/ (Apple II, Firebird 1985). QL code written from scratch, without copying comments.

## Decisions
- Screen: mode 8 (256x256). Space view 256x136 centred at (128,68), like the Apple II; the lower panel uses the extra rows.
- Drawing goes directly in the QL format (gfx.c). PC backend with the same format to test the logic without hardware.
- Logic in C (c68); critical loops (lines, 3D projection) will move to 68000 assembly after profiling.
- Disk: saving/loading the commander to a QDOS file (flp1_/mdv1_), replaces rwts.

## Platform layer (done, tested on PC)
pixel, xor_pixel, get, line (normal/XOR), hline, rect, clear.

## Text (done, tested on PC)
text.c: 8x8 cells (32x32), ink/paper/transparent, \n \r \b, line wrap, row clearing, XOR block cursor with blinking. Public-domain font (font8x8_basic, generated with tools/gen_font.py).

## Arithmetic (done except what depends on the game state; tested on PC)
emath.c: DORND, MULTU/MU11, SQUA, MULT1/MULT12, MAD, ADD, MULTS, FMLTU/FMLTU2 (log and sine tables), MLTU2, MLU1/MLU2, MULT3, TIS1/TIS2/DVID96, LL5 (square root), LL28/LL61 (division by logarithms), LL38, DVID4/DV41/DV42, DVIDT, DVID3B. `make test` compares ~895,000 cases with a literal transcription of the 6502.
Those that depend on the game state are in ship_math.c (see the next section).

## Game state and dependent arithmetic (done on PC, tested)
- `state.h/state.c`: ship block INWK (37 bytes; `I_*` offsets), K% table (`ks`, NOSH+1 slots of NI bytes: one spare because UNIV has NOSH+1 entries), `univ[]` (UNIV), `frin[]` (FRIN, NOSH+1), `many[]` (MANY; `sspr` = many[SHIP_SST]), junk/auto/ecmp/mj, zero-page workspace (P+2, K3/K4 contiguous in `zk3[16]`, XX15, XX12, XX16) and the QQ* and commander variables with the original's sizes (CASH big-endian). `state_clear()` zeroes everything and initialises UNIV. K, P, P+1, Q, R, S, T, U remain in emath (zK, zP, zP1...).
- `ship_math.c`: MVT3, MAS1-MAS4, TAS1, VCSUB/VCSU1, TAS2, TAS3, TAS4, TAS6, NORM, TIS3, TIDY, SPS1-SPS4, PLS6 and PROJ (PLS6 and MVT3 were not in the list but are direct dependencies), LCASH/MCASH/GCASH, SCALEX/SCALEY/SCALEY2. It respects the 6502's fall-throughs between routines (TAS2 -> NORM, SPS1/SPS4 -> TAS2, TIS3 -> DVIDT, TAS3/TAS4 -> MAD, SCALEY -> SCALEY2, LCASH -> MCASH) and the input/output carries (e.g. SQUA2 always exits with C = 0). TAS5 does not exist in this version.
- Test: `make test_state` (part of `make test`): tools/ref6502_state.py transcribes the 6502 literally, tools/gen_vectors3.py generates 81,000 cases (27 routines x 3,000, with random inputs and boundary values) and tests/test_state.c compares them. Verified with mutations: the test detects one-bit changes in carries, signs and branches.
- Known limits: V (pointer of VCSUB/TAS1) is passed as a pointer; the Y offsets of MAS2/MAS3 are 0 or NI (slots 0 and 1), as in the original; the 6502 transcriptions are our own, not the binary (see tests against the original).

## Keyboard and joystick (done on PC; QL backend untested)
keys.c: KEYROW matrix through the IPC (command 9), simultaneous keys, edges, character queue (UK, provisional), CTL1 (cursors+space) and CTL2 (F1-F5) joysticks, Elite flight controls. `make test_keys` (27 tests). QL backend: keys_ql.c + ql_ipc.s (trap #1 MT.IPCOM). `make ql_keys` generates an interactive demo to validate on the QL.

## Sound (done on PC; QL backend untested)
sound.c: the original's effects (SOBEEP, SOBLIP, SOEXPL, SOHISS, SOBOMB, LASNOISE, BEEP, BOOP, BELL, EXNO*, DEATH) translated to the IPC's BEEP (command 10) with the 6502's timings; BEEP OFF (11); priorities so that a minor effect does not override a major one; snd_enable = DNOIZ. `make test_sound` (26 tests). `make ql_sound` generates a demo to tune by ear (SND_NOISE_FUZZ/RND). Noise and sweeps are approximations: the QL's pitch is not linear and it could not be heard.

## Universe (done on PC, tested against the oracle)
universe.c: galaxies, systems, market, distance, galactic hyperspace and descriptions, ported from TXTELITE.C 1.5 (Ian Bell). `make test_universe` compiles the original TXTELITE.C as an oracle and compares 8 galaxies: systems, descriptions and markets identical (12,288 records); distance follows the 6502 algorithm (verified against an independent version on 131,072 pairs), not Text Elite's floating-point calculation. Demo: `make host_demo_universe` / `make ql_universe`.

## c68 runtime console (QL)
- `plat_ql.c`: `plat_init` redefines the console window as full screen, black border and no cursor (SD.WDEF/SD.CLEAR/SD.CURS) and registers `plat_shutdown` with `atexit`.
- The console keyboard queue is emptied with IO.FBYTE (timeout 0) at start-up, on every `plat_present()` and on exit, so that SuperBASIC does not receive the keys. `ql_trap3` (in `ql_ipc.asm`) is the generic trap #3 stub.
- Pending validation on a real QL/emulator (QPC2, uQLx, sQLux): that `fgetchid(stdin)` returns the right channel and that no key presses are left on exit.

## 3D projection (done on PC, verified against the original)
- `shipdata.c/.h` (generated by tools/gen_shipdata.py): 32 ship blueprints in one block; some share edges/faces with another blueprint (signed 16-bit offsets), which is why pointers are built with `bp_ptr`.
- `ship3d.c`: LL9, LL51, SHPPT, CLIP/CLIP2 (LL118/120/123/129), LSPUT/LSCLR. Hooks: `ship_loin_hook` (default gfx_line XOR), `ship_doexp_hook`, `ship_planet_hook`. `ship_c_in` = LL9's input carry.
- Verification: `make test_orig` runs the original code in a 6502 emulator (see tools/README_ref.txt). Pending: DOEXP, PLANET/SUN/CIRCLE, STARS, DIALS, SCAN, MVEIT; apply the same verification to ship_math.c and emath.c.
- Demo: `make host_demo_ship` (PC) and `make ql_ship` (QL, untested).

### 2.1 Workflow for porting a routine

1. Read the routine in `elite-source.asm` (look for `;       Name: X`; multi-part routines are called `X (Part n of m)`). Extract the code without comments: `sed -n A,Bp elite-source.asm | sed 's/;.*//' | grep -v '^\s*$'`.
2. Write the C **transcribing the flow** (with `goto` if needed, including jumps into the middle of routines and fall-throughs from one routine into another) and **modelling the carries** the 6502 uses (`em_carry`, `em_rand_c`, local `c`/`cc` variables). If an instruction depends on the carry a subroutine returns with, that carry must be computed (example: `MLTU2`'s is the low bit of the product).
3. If it uses `int d` with comparisons: **compute the sign/carry BEFORE truncating to `u8`** (c68 `-O` bug, section 10).
4. Add the line to `tools/ported.txt` (`NAME C_function[,other] state note`; states: `verificada | transcripcion | sin-verificar | propia | parcial | no-necesaria`) and the row to `PENDIENTES.md`; run `python3 tools/inventory.py`.
5. Own tests in `tests/` (to prove the C does what is intended) and, if applicable, a **c68 probe** in `tests/c68/probe_*.c` (add it to the list in `tools/c68_check/run.sh`) to check that c68 compiles the same as gcc.
6. Verify against the 6502 when there is an opportunity (section 5): run the original routine in the emulator with random inputs and boundary values, compare, test with one-instruction mutations, and move the row to `verificada`.

## 3. Environment and tools

### 3.1 What is in the sandbox and what is lost
The sandbox (`/home/claude`) may be lost between sessions. Everything important is in the tar. What has to be reinstalled each time: the reference source (`moxon-appleII/` in the project root), the qcc toolchain (`/tmp/qlsdk`, with `tools/install_xtc68.sh`), `qemu-user` and `gcc-m68k-linux-gnu` if missing (`apt`/`pip` as the network allows; in the current session the network allows github.com, pypi and the Ubuntu repositories).

### 3.2 C compiler for the QL (XTC68) — installation
`tools/install_xtc68.sh` automates what follows (tested on 2026-10-17):
1. `git clone https://github.com/stronnag/xtc68` (migrated to Codeberg, but the GitHub clone works) and `git clone https://github.com/xXorAa/c68-support`.
2. Modern gcc fails with `-Werror` on the old sources (e.g. "ignoring return value of write"): `sed -i "s/'-Werror', *//g" src/*/meson.build`.
3. `meson setup build --prefix=/tmp/qlsdk --strip && ninja -C build install` → `bin/{qcc,c68,as68,qld,qcpp,qdos-ar,...}`.
4. The c68 runtime (`INCLUDE_*` headers and `LIB_*` libraries, from the c68 runtime 4.24 "424frun1") is in a **`support/424frun1`** folder of the xtc68 repository, and is installed with `./sdk-install.sh /tmp/qlsdk` run **from that folder** → `share/qdos/include` and `share/qdos/lib`.
5. Usage: `export PATH=/tmp/qlsdk/bin:$PATH QLINC=/tmp/qlsdk/share/qdos/include QLLIB=/tmp/qlsdk/share/qdos/lib`; `qcc -O -Isrc -o elite ...` (the `Makefile` already does it with `make ql_game`). `-Isrc` is mandatory because qcc looks for the `#include "..."` in the current directory. `qcc` prints `elite: dataspace 18114 (46c2)` when it finishes correctly.
6. `as68` is from the Sozobon family: `.globl`/`.text` directives, comments with `;`, labels with colons, `.asm` files (qcc does not recognise `.s`); `xdef`, `section` and comments with `*` are not valid.

### 3.3 Verification of c68 code (`make c68_check`)
`tools/c68_check/run.sh [probe ...]` compiles each probe in `tests/c68/` with gcc (PC) and with the real `c68` (`-int=16 -O -warn=0`, preprocessing with `gcc -E -P -U__GNUC__ -nostdinc`), converts c68's output (ACK syntax) to GNU as with `conv.py`, links it with a mini runtime (`rt.s`: `.Xlmul`, `.Xldiv`, ..., screen output) and runs it under `qemu-m68k`. Each probe leaves hashes on the "screen" and they are compared byte by byte. `XTC68=<dir with c68>` (by default `/tmp/qlsdk/bin` if it exists, otherwise `/tmp/xtc68/build`). With `-U__GNUC__` the "QL" paths are compiled (for example the long words of `gfx_fill_lines`). Probes: `gfxfast, emath, keys, ships, game, charts, dash, flight, session`. **It does not replace the real QL** (it covers neither the runtime nor the hardware), but it detects compiler bugs (it found the `-O` one).

### 3.5 `elite.img` disk image (qltools)
`make elite.img` (alias `make disk`) does everything at once and is repeatable:
1. **`elite`** (the real dependency, `ql_game` is now an alias of `elite`): builds with qcc if any `src/*.c`, `src/*.h` or `.asm` changed. qcc leaves at the end of the file the `XTcc` trailer + dataspace (big-endian; today 16,840 bytes); qltools detects it on writing and marks the file as executable with that dataspace (`E` in the directory). qltools' `-W` is needed; do not copy the file by hand.
2. **`$(QLTOOLS)`** (`tools/qltools_src/Unix/qltools`): if it does not exist, `git clone --depth 1 https://github.com/NormanDunbar/qltools tools/qltools_src` and `make -C tools/qltools_src/Unix`. Another already installed can be used: `make elite.img QLTOOLS=/path/qltools` (variables `QLTOOLS_REPO`, `QLTOOLS_DIR`, `DISK_LABEL`, `ELITE` by default).
3. `rm -f elite.img`; `qltools elite.img -fdd ELITE` (formats DS/DD: 2 sides, 80 cylinders, 9 sectors per track = 1,440 sectors = 737,280 bytes; ID `QL5A`); `qltools elite.img -W elite data/boot data/elite_scr data/elite_dash` (`-W` overwrites without asking; the names on the disk are the file's without the directory); `qltools elite.img -d` lists the result.
- **Contents (checked round trip with `qltools -t -n` + `cmp`):** `elite` (E, ≈123,506 bytes, dataspace 16,840), `boot` (63 bytes, SuperBASIC program: `MODE 8`, `LBYTES flp1_elite_scr,131072`, `EXEC_W flp1_elite`, with QDOS's LF end of line), `elite_scr` (32,768 bytes: the screen loaded at `$20000`), `elite_dash` (7,176 bytes, panel). About 1,107 sectors are left free for saved games (`flp1_elite_<name>`).
- **qltools notes:** it translates `.` into `_` in names (without `-t`); no name on the disk has a dot. It shows the year of the files' date as 126 (presentation-only error). The `-fdd` and `-W` arguments go **before** the file list; to check a file with an untranslated name use `-t -n name`.
- In an emulator (sQLux, QPC2, uQLx): mount `elite.img` as `flp1_` and start with `LRUN flp1_boot` (or let the disk boot run it).

### 5.3 How to verify a new routine against the original
`tools/orig.py` builds a 6502 image with the original routines requested and stubs for those that draw; `tools/gen_laser.py` and `tools/gen_damage.py` are the most convenient examples; they use `tools/frag6502.py` (its `build(lines, None, presets)` turns into stubs that log (name, A, X, Y) everything that is not resolved, and puts a local RTS when a branch does not reach the stub; it assembles loose stretches of the main loop by label: `.MA68`..`.MA3`, `.MA47`..`.MA8`...; `presets` fixes addresses of tables such as `log`; if a branch does not reach a label outside, a local `RTS` must be put in front of it, e.g. `['.out', 'RTS'] + OUCH`). Careful: a stretch that "falls" into the next routine (like `Ze` into `DORND2`) needs that routine right after it in the list; `tools/gen_trade.py` (preprocesses `IF/ELIF`, replaces the screen with stubs, runs `tnpr` and the `TT219`/`TT208` stretches). Steps: dump the random initial state into the emulator and into C, run, compare INWK/variables/drawn lines, repeat with boundary values, mutate an instruction of the C and check that the test fails.


## 6. Technical architecture

### 6.1 Code conventions
- **Pure C89** (no `stdint.h`, no mixed declarations or in `for`); `u8 = unsigned char`; **`int`: the `Makefile`'s `qcc` (without `-int=16`) compiles it as 32 BITS (checked with `qcc -S`: `.data4`); `make c68_check` uses `-int=16`**: do not depend on the size (use `long` for values > 32767 and for everything the assembler reads) for values > 32767 (`SCR_BYTES = 32768L`) and do not rely on promotions.
- The zero-page variables are **C globals** (`zP`, `zP1`, `zQ`, `zR`, `zS`, `zT`, `zU`, `zK[4]`, `em_x`, `em_carry`, `em_rand[4]`, `em_rand_c`, `zk3`, `zx15`...). The original's names are in lower case; sizes and byte order are the 6502's because the routines index with offsets (`INWK+10,X`).
- **INWK** (current ship) has **NI = 37 bytes** (includes XX19 and NEWB); `I_*` offsets in `state.h`: pos x/y/z (3 bytes each: lo, hi, sign) 0–8; nose 9–14, roof 15–20, side 21–26 (6-byte vectors: x lo/hi, y lo/hi, z lo/hi); speed 27, acceleration 28, roll counter 29, pitch counter 30, state 31, AI 32, heap pointer 33–34 (not used in C), energy 35, NEWB 36. **K%** (`ks`) has `NOSH+1 = 9` slots of NI bytes (the last one spare); `state_slot(n)` gives the slot; `frin[n]` is the type (0 = free; `frin[NOSH]` acts as terminator); `many[type]`; `sspr = many[SHIP_SST]`.
- **Bits of `INWK+31` (state):** bit 7 = ship destroyed or about to explode, bit 6 = explosion cloud drawn, bit 5 = exploding, bit 4 = dot drawn on the radar, bit 3 = lines drawn in the heap, bits 0–2 = blueprint's line indicator.
- **Routines with carry:** the 6502 uses the carry as a parameter and result; the C models it with variables (`em_carry`, `em_rand_c`, `c`). Multi-part routines with jumps into the middle are transcribed with `goto`.
- **LL9 hooks** (`ship3d.h`): `ship_loin_hook` (line drawing; by default `gfx_line` in XOR), `ship_doexp_hook` (= `doexp`), `ship_planet_hook` (= `planet`); `ships_hooks()` sets them. LL9 input variables: `ztype` (TYPE), `zxx0` (blueprint, `SHIP_BP`), `zxx19` (the ship's line heap), `zinf` (the ship's K% block).

### 6.2 Flight loop (`flight.c`, `space.c`, `ships.c`)
Each frame of `flight_run`: read keys (`key_ctx_flight` + `ctl_read`), `space_controls` (turns with `cntr`/`BUMP2`/`REDU2`, `ALPHA/BETA/ALP1/BET1`, speed `DELTA`), **`laser_fire`** (part 3: if `LASCT = 0`, fire pressed, `GNTMP < 242` and a laser in the view → `LAS`/`LAS2`, `LASNOISE`, `LASLI`), `space_step` (= `mcnt++`, **`ships_step(view)`**, **`energy_tick`** (every 8 frames, shields with `SHD` and energy `+ENGY+1`), altitude, events), **`laser_frame_end`** (part 16: `LASLI2` erases the lines if `LASCT < 8`), dust (`stars_update`), **`dly_tick`** (the message expires), **`laser_cool`** (`MLOOP`: `GNTMP−1`, `LASCT−2`), panel (`dash_update`), sight, `plat_present`. On launch, `combat_reset` (= `DOENTRY`: energy and shields to 255, cold laser). `space_step` also calls **`damage_checks`** (part 15, every 32 frames: at 10, ENERGY LOW if energy ≤ 50 and altitude with `MAS2`/`MAS3`/`LL5` (below 37 → death); at 15, DOCKING COMPUTERS ON; at 20, cabin temperature `~MAS3(sun) + 30 + C` (overflow → death; ≥ 224 with scoops → fuel `+ DELTA/8` up to 70 and FUEL SCOOPS ON)). The `SPACE_EV_DOCK` and `SPACE_EV_DEATH` events end the flight: `FL_DOCK` or **`flight_death`** (= `DEATH`: sound, view erased, GAME OVER, `D1` debris and 65 frames) and `FL_DEATH`, with which `game_run` returns to the title (`DEATH2`).
- **Damage (`damage.c`):** `oops(damage, carry)`: the shield on the side of the ship that hits (sign of z in its K% block) absorbs; the shortfall comes out of energy; energy 0 or negative → `player_dead`; if we survive without shield, `EXNO3` and `OUCH` (50 % × 22/256: the cargo or equipment `QQ20+X` is lost, X = 0..21, with a "... DESTROYED" message through `mess_de`).
- **`ships_step`** (per-ship loop of the reduced main loop): for each slot `n` with `frin[n] != 0`: loads INWK from K%, sets `ztype/zinf/zxx19/zxx0`, **`mveit()`**, copies INWK to K% (MAL3), **`combat_collide()`** (parts 9 and 10, in space axes: if the ship is less than 64 away on all three axes (128 the station) and not exploding: with scoops and below us, cargo and anything with a commodity in byte 0 of the blueprint is scooped (`tnpr1`, message with the name; if it does not fit, it is destroyed with `EXNO3`); the station: `ISDK` (not hostile, nose `INWK+14 ≥ 214`, planet in the cone `XX15+2 ≥ 89`, slot `|INWK+16| ≥ 80`) → **docking** (`SHIPS_EV_DOCK`), otherwise, with `DELTA ≥ 5` **death** and otherwise braking and damage 5; the rest: the other ship is destroyed and we receive `128 + energy/2` with `OOPS`), **`plut(view)`**, **`combat_hit()`** (part 11: `HITCH`; with `LAS` ≠ 0, `EXNO`, damage = `LAS` (station: none; Constrictor and Dodo: only the military laser, at 1/4), if the energy runs out: bit 7 of `INWK+31`, splinters if it is an asteroid with a mining laser, `SPIN` of plates and cargo (`SFS1` creates the child ships from the mother's K% block), `EXNO2` (TALLY with `KWL%`/`KWH%`, "RIGHT ON COMMANDER!" if the high byte rises); always `ANGRY`), **`ship_ll9()`** (draws or erases with XOR), stores energy (byte 35); then it removes the ship if **`combat_killed()`** (NEWB bit 7, or the explosion finished: `FIST |= NEWB bit 6` and, if there is no message (`DLY`) or `MJ`, bounty from blueprint bytes 10–11 with `MCASH` and a message with the money), if it is far away (`FAROF`: some high coordinate > 224) or, for the station, if it moves away (own rule: `z_hi > 0x30`), and in that last case the sun returns. `ship_kill` shifts the slots and their heaps.
- **Line heaps:** one 256-byte heap per slot (`heaps[NOSH]` in `ships.c`) instead of the original's `SLSP` allocation. Erasing a ship without going through LL9: `zxx19=heap; zlsnum=1; zlsnum2=heap[0]; ship_lsclr();`. When erasing the view area (`clear_view`) the lines must be **forgotten** (`ships_forget_lines()`, `sun_forget()`), because drawing is XOR: if the heap believes there are lines and they are not there, the next pass draws garbage.
- **Planet, sun and station:** `ships_launch()` (planet in slot 0 and station in 1; own placement of the station), `ships_arrive()` (planet and sun; the sun is behind: negative z). `planet()` = `PLANET`: if `z_top >= 48` or `z == 0` or `PROJ` fails → removes (`WPLS2` or `WPLS`); otherwise, `DVID3B2` gives the radius, and it draws `SUN` (odd type) or `WPLS2`+`CIRCLE` (even type). **`circ_lsy2[0]` must be `$FF`** (sentinel of the ball's heap).
- **`MVEIT`** (`move.c`): part 1 (TIDY every 16 frames; `TACTICS` if `INWK+32` bit 7, via `move_tactics_hook`, empty today); `SCAN` (radar); parts 2–5 (advance along the nose `INWK+27`, acceleration and blueprint maximum speed, rotation of the position by our roll/pitch with `MLTU2`/`MVT6`); `MV45` (z −= DELTA, rotation of the vectors by our turns with `MVS4`, the ship's roll and pitch counters with `MVS5`, and radar). Planets and suns (type ≥ 128) go through `MV40`. **Mind the carries:** `MLTU2`'s comes from the low bit of the product (`((zP^$FF)&zQ)&1`).
- **Planets and suns (`sun.c`):** `loin()` and `hloin()` reproduce the **memory effects** of the original's `LOIN` and `HLOIN` (endpoint order, `SWAP`, `P`, `Q`, `S`; `HLOIN`'s rounding to even), because `WPLS2` and `SUN` depend on them; the drawing itself is `gfx_line`/`gfx_hloin`. Test hooks `sun_loin_hook`/`sun_hloin_hook`.
- **Flight equipment (`flight.c`):** `B` bomb (`bomb_key`; each frame `bomb_frame` = part 16; in `ships_step` the bomb destroys everything except station, Thargoids, Constrictor and Dodo; `view_extras` draws the bolt again after erasing the view), `J` jump (`warp`, and LOOK1: new view; the radar's M bulb warns when it is blocked), `ESC` pod (`flight_escape`: `ships_escape` + cargo, FIST, pod to zero, 70 fuel, docking), `C` docking computer (`dock_auto`; each frame `dokey_auto` adds its keys and adjusts `JSTX`/`JSTY`/`DELTA`) or, without it, provisional immediate docking, `P` switches it off; `MJP` (`misjump`) on 0.78 % of the jumps.
- **AI (`tactics.c`):** `mveit()` calls `tactics()` (hook `move_tactics_hook`, set by `ships_hooks`) every 8 frames for each ship with AI (`INWK+32` bit 7) and on every frame for missiles. With X = TYPE: missile (`TA18`: ECM → explodes; target = slot `(IA & $7F) >> 1` or us with bit 6; on reaching it, `EXNO2` with X = slot, like the original), station (shuttles or, if hostile, police with `SFS1` AI $F1), rock (releases a ship), Thargon without mother ship (stops), and for the rest: recharge energy, trader/bounty hunter/hostile/pirate according to `NEWB`, dock (`DOCKIT`) or go to the planet (`GOPL`) if not hostile; if it is: the Anaconda releases ships, random roll, pod if almost out of energy and it carries one (`E%` bit 7), missiles (`INWK+31` bits 0–2) or Thargons, laser (`INWK+31` bit 6 draws it in LL9; if it aims straight at us, `OOPS` with half of blueprint byte 19) and the turn (`TA4`..`TA10`). If `OOPS` kills us, `ships_step` returns `SHIPS_EV_DEATH`. `KS2` (in `ship_kill`) readjusts the missiles' targets; `KILLSHP` warns TARGET LOST and points at the Constrictor (`TP`, `TALLY+1`).
- **Missiles and ECM (keys):** `T` arms (looks for a target: white indicator, `MSAR`), part 11 locks the target on passing through the sight (beep, red), `M` fires (`FRMIS`), `U` disarms; `E` ECM (if carried): `ECMA` = 32 frames of sound, uses energy every frame and makes missiles explode; ships with ECM (AI bit 0) use it against our missiles.
- **Explosion:** LL9 marks it (`INWK+31` bit 7 → bit 5, `zxx19[1..6]` initialised) and calls `DOEXP` every frame: it erases the previous cloud (`PTCLS` in XOR), makes it grow, draws it; at the end `EX2` sets bits 7 and 5 and `ships_step` removes the ship. The original's colours are 4 from the Apple II (blue, red, "fuzzy", other): here cyan, red, yellow and white.
- **Laser (`combat.c`):** `LAS` = power of this frame (0 if it does not fire), `LAS2` = there are lines on screen, `LASCT` = pulse count (`power AND $FA`: 10 for pulses → one shot every 5 frames, visible 2; 0 for beam and military → draws and erases in the same frame; 50 for mining), `GNTMP` +8 per shot and −1 per frame (at 242 it does not fire), `DENGY` −1 energy per shot. The lines go from (`LASX`, `LASY`) (centre ± random) to (32, 135), (224, 135), (48, 135), (208, 135) in XOR with `LASER_COL` (white: the original sets no colour). `clear_view`/`redraw_all` call `laser_forget()` (`LAS2 = 0`, like `TTX66`). Messages: `mess(token)` (0 = money, 100 ENERGY LOW, 101 "RIGHT ON COMMANDER!", 108–115 equipment, 123 DOCKING COMPUTERS ON, 160 FUEL SCOOPS ON, 208+i commodity i; the original's tokens) paints on row 24 with `combat_mess_hook` and sets `DLY = 20`.
- **Test contacts (provisional):** `N` (`ships_spawn`) creates a random ship ahead (z_hi 2–5, speed = maximum/8) and `K` (`ships_explode_nearest`) sets bit 7 of the nearest one. They will be removed with the encounters.

### 6.3 Graphics and text
- **Graphics:** each word is 4 pixels; it is written directly to the screen (`$20000` on the QL, memory on the PC with the same format; `tools/ql2png.py` converts it to PNG). 256×136 space view centred at (128, 68) like the Apple II; the panel goes on lines 136–191 (the original's bitmap) and the QL's extra rows are left for messages. XOR for everything animated (erase = redraw).
- **160-line native flight view (2026-10-19):** `view_set_native(1)` (state.c; active only inside `flight_run`, switched off in `flight_screens`, title, docked and charts) sets `view_cy = 80`, `clip_h = 160` and `view_yscale = 1`. **Projection:** vertical offsets are multiplied by 6/5 (`v + v/5`) in `LL9` (vertices, before adding to the centre) and in `sm_proj` (SHPPT and planets); clipping (`LL118/120/123/129/145`, `CLIP`) uses `clip_h` (`YC2M1 = clip_h - 1 = 159`). **Planet, sun and tunnel circles** are calculated in the original's space (centre 68, `sun_yx2m1 = 133`, `clip_h = 134`, no 6/5) between `view_virtual_begin/end` (sun.c; `sun_draw`, `sun_wpls`, `circle_draw`, `circle2_draw`, `circle_wpls2` and `planet` already do it by themselves) and are drawn with chart transformation mode 3 (`y' = 80 + (y - 68)·6/5`, replicated rows in `HLOIN`, transformed ends in `LOIN`): they come out as ellipses 1.2 taller. **Others:** dust (`pixel2`), bomb bolt and sight (`chart_sight`, mode 3) go through `view_ty`/mode 3; laser: centre `view_cy` and base `clip_h - 1`; explosion `xr < clip_h - 1`. **Panel:** its routines keep the original's coordinates (136..191) and `gfx_yoff_set(24)` (only with the native view; `panel_y` in dash.c and `space_scan`) moves them down to 160..215 (`DASH_Y0 = 160`). `VIEW_H = 160`; `scr_box` does not draw `BOX` in flight. Under the panel there are **5 text rows** (27..31): messages (`ROW_MSG`), VIEW, HERE, TARGET and a rotating help line (`HELP_FRAMES` = 100, ≈2 s at 50 fps; provisional). With the native view off (tests) everything is identical to the original and the tests against the 6502 stay green.
- **Fast:** `gfx_fill_lines` (fill of whole lines with unrolled long words) and `gfx_copy` (copy with long words if the addresses are even). On the PC they use bytes (without depending on aliasing rules); `c68_check` checks that c68's long-word path gives the same.
- **Text:** 8×8 cells (32×32), ink/paper/transparent, blinking XOR cursor; public-domain 8×8 font (`gen_font.py`). The original's compressed text engine is **not ported**: the texts are C strings (`menu.c`, `universe.c`).

### 6.4 Remaining modules (technical summary)
- **Universe** (`universe.c`): `uni_distance` follows the 6502 algorithm (`dx²+(dy>>1)²`, `LL5`, ×4, with saturation), not Text Elite's floating-point `sqrt` (which only matches in 14 % of the pairs). The galactic jump goes to the system nearest (0x60, 0x60). Planet radius on the local chart: `(w2hi AND 1) + 2 + C` with C `cpl`'s carry.
- **Charts** (`chart.c`, `sun.c`): 192 × 96 px galactic chart with frame (x 32..223, y 19..115); local chart with 3 px/unit in x and 1.5 in y centred at (105, 75), only systems less than 7.0 LY away; circles with `SUN`/`CIRCLE`; `HLOIN` = `gfx_hloin` (ends to even, covers X1..X2−1).
- **Trade** (`game.c`): `tnpr` rules; with `TRADE_FAITHFUL 1` (default) two peculiarities of the original are reproduced (see 10.3).
- **Panel** (`dash.c`): full `DIALS` with the cache of what was last drawn (`dials`, `dialc`), `COMPAS`, missiles (`msbar`), S and E bulbs. **Energy** drops with each shot and with hits and recharges; **laser temperature** goes up and down; **shields** drop with collisions (and will drop with enemy shots once `TACTICS` exists); **cabin temperature** rises near the sun.
- **Stardust** (`stars.c`): `STARS1/6/2` (front, rear, sides with `ST2`), `FLIP`, `NWSTARS`, `PIXEL2`.

## 7. QL hardware

- **Screen (mode 8):** word = 4 pixels; for pixel k (0 to 3, left to right) with `s = 2*(3-k)`: even byte with green in bit `s+1` and flash in bit `s`; odd byte with red in bit `s+1` and blue in bit `s`. 128 bytes per line. Colours: bit2 = green, bit1 = red, bit0 = blue (`C_*` in `platform.h`).
- **Console (c68):** `plat_init` redefines the window as full screen, black border and no cursor (SD.WDEF, SD.CLEAR, SD.CURS) and registers `plat_shutdown` with `atexit`; the console keyboard queue is emptied with IO.FBYTE (timeout 0) at start-up, on every `plat_present()` and on exit (KEYROW does not consume key presses and SuperBASIC received them). `plat_exit()` cleans the console and removes the job with `MT.FRJOB` (`ql_trap1`) to avoid "Press a key to exit". `plat_wait_key()` (wait for a key press) **confirmed on the real QL**.
- **Keyboard:** `KEYROW` through the IPC (command 9), one call per row (0–7); 8-byte `MT.IPCOM` block `9,1,0,0,0,0,<row>,2`, reply in D1.B. **Each row is a slow call**: `key_ctx_menu()` reads rows 1 and 7 always and the rest rotating (3 reads per frame); `key_ctx_flight()` reads rows 1, 3 and 4 always and 0, 2, 5, 6 and 7 rotating (4 reads). A key in a rotating row is detected within at most 5 (flight) or 6 (menus) frames. `KEYROW` reads the physical keyboard even if another window has the focus; three keys in a matrix rectangle give a ghost. **Joystick:** on the QL they are keys: CTL1 = cursors and space (row 1), CTL2 = F1–F5 (row 0). Provisional UK layout of the menus; CTRL+Left gives character 8.
- **Sound:** `BEEP` through the IPC (`MT.IPCOM`), command 10 with 8 parameter bytes (`$0000AAAA`), 15-byte block with interval and duration **low byte first** and **reply 1 (none)**; `BEEP OFF` = command 11 (also with reply 1). **If a reply that the 8049 does not send is requested, the link gets out of sync and the QL hangs** (2026-10-22). A new `BEEP` cancels the previous one; do not sound while a job is being loaded or unloaded. Pitch = 0.022457·cycles − 9.6 (frequency = 22917 / (2·(pitch + 9.6)) Hz); duration and interval in steps of 43.64 µs (the 8049 gives 22,917 per second; the manual's 72 µs is wrong). All the original's effects are translated from the 6502 loops, with priorities; `snd_enable(0)` = DNOIZ. **Not fully heard:** noise and sweeps are approximations (`SND_NOISE_FUZZ`, `SND_NOISE_RND` by ear; the sign of upward sweeps is a hypothesis).
- **Trap #3:** `ql_trap3(d0,d1,d2,d3,a0,a1)` in `ql_ipc.asm` loads registers, executes `trap #3` and returns D0 (0 ok, negative QDOS error). Codes: IO.FBYTE=1, SD.WDEF=$0D, SD.CURE=$0E, SD.CURS=$0F, SD.CLEAR=$20; from `qdos.h` only `fgetchid` and `mt_dmode` are used.
- **Disk:** `elite.img` image with `make elite.img` (3.5); boot through the `boot` file. QDOS files from C (`fopen`/`fwrite`): `flp1_`, `flp2_`, `mdv1_`, `mdv2_` (or a directory on the PC). Data go as `<drive>elite_dash` (panel) and `<drive>elite_<name>` (saved games). The game silences sound before touching the disk.
- **Memory:** screen at `$20000` (32 KB); `uni_galaxy[256]` ≈ 8 KB; K% 333 bytes; ship heaps 2 KB; total dataspace 18,114 bytes. No memory map of the game yet; target ≤ 640 KB.
- **Performance:** the 68008 is slow and the bus is 8 bits wide. LL9 in C has only been measured on the PC. Erasing the view went from ≈35,000 calls to `gfx_pixel` to 544 iterations of 8 long writes. If more is needed: an assembly routine with `movem.l` for the fill, and `LOIN`/`LL9` in assembly after profiling.

## 8. Controls

- **Flight:** cursors = roll (left/right) and pitch (up = dive, down = climb; also the CTL1 joystick); **`F` accelerates, `D` brakes**; **`A` or space laser** (hold down); `B` bomb, `ESC` pod, `T`/`U`/`M` missile, `E` ECM, `J` jump, `C` and `P` docking (the equipment ones still without function); **`1`–`4` views** (front, rear, left, right); **screens, the same in flight and docked: `5` galactic chart, `6` short range chart, `7` system data, `8` market prices, `9` status and `0` inventory**; `H` hyperspace (requires a target system in range), `G` galactic jump, **`C` docking computer** (if carried) and **`P` switches it off** (docking is also possible by entering through the slot), **`B` energy bomb**, **`J` jump within the system**, **`ESC` escape pod** (Shift+ESC is still the emergency exit), **`T` arm missile, `M` fire it, `U` disarm it, `E` ECM**; **`=` pause** (`FREEZE`; `O` opens the own "OPTIONS" window, with each option, its key and ON/OFF, `ESC` returns to the menu and `-` to the game; `pause_options` in flight.c): with the game paused, `D` damping, `A` keyboard recentring, `X` authors and manual failed jump (`TAB` during hyperspace), `F` flashing bars, `Y` joystick Y axis, `J` joystick axes, `K` joystick (CTL1), `U` capitals only in the mission texts, `T` tape/disk, `Q`/`S` sound off/on, `ESC` returns to the title and `-` continues (tables `TGINT`/`DKS3`). `N`, `K` and `C` without computer only work in the tests (`flight_testkeys`).
- **Docked:** `H`/`G` show DOCKED (`dockEd`); **`U` launches (undock)**, `1` buy, `2` sell, `3` equipment, **`4` does nothing**, `5`–`0` as in flight (see above), `I` disk. `/`, `,`, `.`, `S` and `X` are no longer used.
- **Equipment (docked, `3`):** cursors + ENTER buy; `5`-`0`, `1`, `2`, `U`, `I` change screen without ESC; for lasers, the view is chosen with the cursors (ENTER/ESC; `0`-`3` too).
- **DEBUG (default build, see history 2026-10-19 and 2026-10-20):** SHIFT-1/2/3 free buying, selling and equipment (red title); in flight SHIFT-C automatic docking, SHIFT-P instant docking, SHIFT-J station near, SHIFT-H jump without fuel limit, SHIFT-F fps counter, SHIFT-D skip maths/ship drawing (profiling).
- **Charts:** cursors move the crosshair, `F` searches for a system (docked only, `HME2`), `D` = `hm`, `O` = `ping`.
- Implemented in `ctl_read()` (keys.c) and `ui_nav()` (menu.c).

## 9. Data formats

- **Commander** (`cmdr.c`): 77-byte block (#0..#76), `CB_*` offsets; `cmdr_pack/unpack`, `cmdr_default` (JAMESON, Lave; factory constants `$03`, `$27`, `$AA`), sealed like `SVE` (`CHK3`, `CHK`, `CHK2 = CHK ^ $A9`). The original's `CHECK`/`CHECK2` only detect 57 % of one-bit changes (not a bug of the port). Money in big-endian (tenths of a credit).
- **Saved-game file** (`save.c`): our own, **94 bytes**: `ELQD`, version, seed, 8-byte name, 77-byte block encrypted with XOR. Name `<drive>elite_<name>`. `load_commander` validates `CHK` and `CHK3` and sets `cok` bit 7 if only `CHK2` fails, like `DFAULT`. (The original's `MUTILATE` encryption is not ported: it is anti-tampering.)
- **`elite_dash`:** `ELQD` header + 56 lines of 128 bytes in mode 8 (violet → magenta, orange → red), generated from `A.SCREEN.bin`; it is read **only once, at start-up (`main`)**, and stored in `dash_bg[]`. Without the file a minimal panel is drawn. It can be edited on the PC: `make dash_png` → `data/cabina.png` → drawing program (the QL's 8 colours) → `make dash_from_png` (`tools/png2dash.py`; colours that are not exact are taken to the nearest and a warning is given). The game paints over it the bars, compass, radar, missiles and bulbs.
- **Ships** (`shipdata.c`): 32 blueprints (20-byte header, 6-byte vertices, 4-byte edges, 4-byte faces) in a 7,154-byte `ship_blob` block (some blueprints share edges/faces through 16-bit offsets); `SHIP_BP(type)`; `SHIPT_*` with the source's names (`SHIPT_CORIOLIS=2`, `SHIPT_DODO=32`...). Header bytes used: 5 (heap size), 7 (explosion), 13 (full drawing distance), 14 (energy), 15 (maximum speed), 19 (line flags).

## 10. Traps, rules and findings

### 10.1 Compiler (c68)
- **`-O` optimiser bug (2026-10-16):** in `x = (u8)d; cc = (d >= 0);` c68 uses the flags of the `move.b` for the `sge` instead of those of the word `d`; it gives a wrong result when the byte comes out positive with `d` negative (on the QL: ships 3 times wider or unrecognisable). **Rule: always compute the carry/sign BEFORE storing the byte** (`cc = (d >= 0); x = (u8)d;`). Applied in 25 places of `ship3d.c` and `ship_math.c`; in the new code (`move.c`, `ships.c`) too.
- **The same bug again (2026-10-18, found by `make c68_check`, probes `missions` and `session`):** in `dt_bprnt` (detok.c), `d = k[x] - tens[x] - borrow; x15[x] = (u8)d; cy = (d >= 0);` gave another carry with c68 and the numbers on the data screen came out wrong on the QL. Fixed by computing `cy` before truncating. **Rule: in all new code with subtraction and carry, the sign before the `(u8)`**, and add a c68 probe for each new module (the probes of rounds 13-15 are in `tests/c68/probe_missions.c`). Two uses of the pattern remain in `sun.c` (lines of `x = (u8)d; c = (d >= 0)`) that the probes consider fine; if they ever fail, that is the first thing to look at.
- `int`: with `-int=16` (`make c68_check`) it is 16-bit and the sine table of `shipview.c` is `long` (32768 overflowed); with the normal `qcc` of the `Makefile` it is 32-bit (2026-10-22). **The assembler must not read `int` variables by symbol** (only `u8` and pointers): `int` values are passed as `long` arguments.
- **`c68_check` probes (2026-10-18):** on the PC `unsigned long` is 64-bit; a linear congruential generator in a probe (`r = r * 1103515245UL + 12345UL`) gives another sequence than in c68 (32 bits) and the probe comes out DIFFERENT without c68 failing. It has to be masked (`& 0xFFFFFFFFUL`).
- `qcc` looks for `#include "..."` in the current directory: always `-Isrc`.
- No `float`; no `stdint.h`; assembly files `.asm`.

### 10.2 QL environment
- IPC: slow row reading (read only the necessary ones); a new `BEEP` cancels the previous one; do not sound during job loads.
- The c68 console clears the screen on exit and writes "Press a key to exit" (avoided with `MT.FRJOB`, **not checked on the QL**).

### 10.3 Findings about the original that are reproduced
- `tnpr` adds in **8 bits**: with 193 or more units of an item in kg/g, buying (256 − what you carry) wraps around and is accepted. `GCASH` computes the amount in **16 bits**: a sale of more than 6,553 Cr at once loses the high bits (e.g. 200 kg of platinum). They are reproduced with `TRADE_FAITHFUL 1` in `game.h`; with 0 they are corrected.
- **`PDESC`:** the original sets `NRU% = 0` and walks 256 positions from `RUPLA-1` (foreign memory; it can hang the data screen during mission 1); the port walks the 26 entries. Measured in the emulator: the result almost never changes (1 case in 200).
- **`MT17` (found while verifying, 2026-10-17):** `LDA BUF-1,X` with `BUF = $0100` assembles in zero page (`B5 FF` in the reference binary), so `VOWEL` looks at byte `DTW5 - 1` of zero page, not the last letter of the name: it almost never removes the vowel before "IAN". It is reproduced with `zp_peek` (RAND, INWK and K3; `CHPR` stores each character in `K3`).
- **`MCNT` goes down** (`DEC MCNT` in `TT100`, after `M%`); the port made it go up. It now goes down as in the original and at 0 parts 2 to 4 run; `WARP` sets `MCNT = 1` and `EV = 0`.
- **`DORND` carries:** in `DT6` it enters with C = 0 (`CMP #129`); in `MT18` the first with C = 0, the second with the first's output carry and the rest with C = 0 (`DASC` returns with `CLC`); in parts 2 to 4 each `DORND` carries the carry of the previous instruction (`encounters.c` models them one by one; the entry one comes from `M%` and is approximated by that of the last `DORND`).
- **Apple text-mode text:** `clss` (going past row 23) only moves the cursor to (0, 0) in graphics mode; in text mode the original would hang. The port always moves it.
- **`WPLS2`** needs `LSY2[0] = $FF` as a sentinel; in the original `RES2` sets it on launch (in the port, `sun_forget` and the initial value).
- `LL52` negated with `1-x` instead of `1-x-1` in the first transcription (fixed; found by verification).
- `CHECK`/`CHECK2` only detect 57 % of one-bit changes.
- **Laser (found while verifying, 2026-10-17):** `SHD` is not just "+1 without passing 255": it **falls into `DENGY`**, so charging a shield uses 1 energy. In `SPIN` the `TYA` covers the random number: the quantity of debris is `type AND byte 0 of the blueprint AND 15` (0 or 4 plates; 0, 1, 4 or 5 canisters), only with a 50 % probability. In `SFS1` the speed of the debris is the `X` left by `DORND` (random 0–15), not the type. The `DORND`s of `LASLI`, `SPIN` and `SFS1` receive carries that come from the code's own `ADC`/`CMP` (`em_rand_c` is set by hand; after `NWSHP` it is 1 if there was room).
- **Laser (original behaviour that is reproduced):** with the military laser against a Constrictor the `LSR LAS` leaves the power at 1/4 for the rest of the frame; the station takes no damage but gets angry (`AN2`: `NEWB` bit 2 of slot 1); **the bounty is not collected if there is a message on screen** (`DLY` ≠ 0) or in hyperspace (`MJ`); the destroyed ship leaves in its byte 35 whatever `A` the sound left (here 0).
- **Damage (found while verifying, 2026-10-17):** when scooping a canister the `DORND` enters with C = 1 (left by `CPX #OIL`); altitude is `SQRT(R Q)` with whatever `Q` there was before (may vary by 1–2 units); on crashing into the planet `ALTIT` stays at 255 (the `JMP DEATH` exits earlier). The `SBC` of `OOPS` has no `SEC`: the incoming carry comes from the caller (in a collision, bit 0 of the other ship's energy).
- **Damage (original behaviour that is reproduced):** colliding with a ship destroys it and gives a bounty (but does not add to `TALLY`); with shields exhausted, each hit may destroy cargo or equipment, including the fuel scoop or the energy unit; the remains of our ship in `DEATH` never collide with us (z carries bit 6). In the original `SOEXPL` (the explosion noise) calls `DORND` and consumes random numbers if sound is on; since round 16 the port does too (before it did not).
- **Planets at the edge (bug seen on the QL, fixed and verified, 2026-10-17):** `WPLS2` (erasing the planet) decides whether to copy (X2, Y2) into (X1, Y1) by looking at `SWAP`, which in the original `LOIN` leaves (0, or $FF if it swapped the endpoints). The port drew with `gfx_line`, which does not touch `SWAP`, and whatever `LL145` had set when clipping at the edge remained: with `SWAP` ≠ 0, `WPLS2` drew all the lines from the same point. Lesson: **an own primitive that replaces a routine of the original must reproduce its effects on the variables someone reads afterwards**.
- **SUN:** the `DORND` of the ragged edge receives the carry `LL5` returns with (bit 7 of the remainder); `em_ll5` is now a literal transcription that returns it in `em_carry`. `HLOIN` rounds X1 and X2 to even and, if X2 < X1, leaves X2 = X1. **`RES2` sets `LSX2` and `LSY2` to $FF**: the sentinel of `LSY2[0]` is indeed initialised by the original (on launch), it is not a bug of its own.
- **DOCKIT** looks at `K3+10` (= `XX2+10`, visibility of face 10 of the last ship drawn) to decide whether a ship has docked; it is reproduced as is (`zk3[10]`). In `DOKEY`, a hard roll by the docking computer sets `JSTX = 64` and releases the roll key even if it is pressed.
- **The bomb:** the source version relaunches the bomb (without erasing the previous bolt) if `B` is pressed while it is exploding; the published one (IB disk) prevents it and is the one followed.
- **TACTICS (when porting and verifying, 2026-10-17):** `BIT M32+1` uses as mask the operand of the `LDY #32` instruction (= $20: "exploding"); `EXNO2` after a missile hit receives the target's **slot**, not its type (and `TA352` uses `LDX #PLT`); `FRMIS` falls into `ANGRY` with the A that `SOHISS` leaves; `ANGRY` looks at `TYPE` (the ship in progress), not the type of the one being angered, to decide whether to make it hostile; any ship's ECM uses the same `ECMA` and changes our E bulb; each `DORND` of TACTICS receives the carry of the previous comparison (modelled in `em_rand_c`). In the test, sound is disabled (`DNOIZ` = $FF) so that `SOEXPL`/`SOHISS` do not consume random numbers (since round 16 the port consumes them only with sound on; in the tests `snd_dornd_hook` is not set or those sounds are not reached).
- **`DVIDT` (found while verifying Maths Geometry, 2026-10-18):** after `ASL P; ROL P+1`, the `ASL Q; LSR Q` leaves C = 0, so **bit 7 of `P+1` is lost** and the first `ROL A` shifts in a 0. The C transcription and the Python one (`ref6502b.dvidt`) shifted it in; because of that `TIS3` gave another value and `TIDY` (orthonormalising the ships' orientation) came out different in 44 % of the cases. Fixed in both.
- **`FMLTU` with A = 0 or Q = 0 does not touch the carry** (`BEQ MU3`/`MU3again` before the `CLC`): it exits with the incoming one. In `EXS1` the `EX5` branch then subtracts with C = 1 (no borrow). `em_fmltu` no longer sets `em_carry = 0` in those cases (the caller sets the incoming one).
- **Apple II `LOIN` (when verifying point by point, 2026-10-18):** the slope comes from `log`/`logL`/`alogh` (quotient with logarithms, 255 if there is no borrow), the error starts at S = 128, one dot per x (or y) and it **does not draw one of the endpoints**: in the more horizontal lines that go up, the call's (X2, Y2); in those that go down or are flat and in the more vertical ones, (X1, Y1). The carries entering `S + Q` are always 0. The Bresenham the port used (`gfx_line`) did not match in any case; now `loin_draw` (lines.c) is the transcription and ships, planets, sun, laser and bomb use it. `HLOIN` and `VLOIN` (with `CPIX`, 2 dots wide) already matched in coverage.
- **Start and end (round 21):** `RES2` does much more than the turns: `NOSTM = NOST`, `LSX2`/`LSY2` = $FF, `MSTG` = $FF, `JSTY` = 128 (**not** `JSTX`), turns and `DELTA`/`ALPHA`/`ALP1` = 3, `dontclip` = 0, `Yx2M1` = 135, `SPBLB` if there is a station (`SSPR`), `ECMOF` if the ECM is sounding, `WPSHPS`, `ZERO`, `SLSP = LS%` and it falls into `ZINF`. `RESET` = `ZERO`, `BETA..ALP2` (7 zero-page bytes: turns, `QQ22`, `ECMA`, `ALP1`) to 0, `JSTGY` = $FF, `QQ12` = $FF (docked), `FSH`/`ASH`/`ENERGY` = $FF and `RES2`. In `DFAULT`, `CHK2`, `CHK3` and `CHK` are fixed variables **outside** the copied block (84 bytes: name and `TP`..byte 75); if `CHK` or `CHK3` do not match the original repeats `CHECK` **forever** (anti-tampering) and the port returns an error; bytes 20-21 and 47-50 of the block are unused. `TT170`, `TITLE`, `BR1`, `DEATH2` and `DEATH` are own screen flow: `no-verificable` (not verifiable).
- **Moving and Equipment (round 23):** the carry `MLTU2` exits with (16 rounds of `ROR`/`ADC`) is the last bit shifted out of `ROR P` and is **always 0** (checked with 100,000 pairs); the previous formula (`(~P) AND Q AND 1`) sometimes gave 1 and threw off the ships' `INWK+3` in part 3 of `MVEIT`. `MVEIT` with a planet or sun that has bits 7 or 5 of `INWK+31` reads the blueprint at `XX0` (foreign memory): it does not occur in the game and the test does not generate it. In `EQSHP` the order is: `eq` charges (if there is no money, message and end, even if you already have it), then `pres` returns the amount if you already have it (also missile number 5), and lasers refund the old one with `refund` (POW→4, POW+128→5, Armlas→12, any other→13).
- **Dashboard and Flight (round 25):** `DIS7` calls `MSBARS` twice with the `JSR P%+3` trick (each draws Y1+1 and Y1+2), i.e. 4 `HLOIN` per bar; `DIS1+2` leaves a single `LSR` (fuel is `QQ14 >> 1`); `CPIX` starts with `STA Y1`, which is why the `VLOIN` of the radar stick uses the head's y; `cntr` looks at `auto` before `DAMP` (with the docking computer it always centres). The E bulb is at x = 56 and the S at x = 192, y = 176..183, bit 0 on the left; `ECBT`/`SPBT` are `7F 7F 07 7F 7F 07 7F 7F` and `7F 7F 07 7F 7F 70 7F 7F`. `MJP` in the IB variant repeats `GTHG` until there are 3 Thargoids and leaves `NOSTM = 2` (in the `_SOURCE_DISK_CODE_FILES` variant it is another condition). In `TT110` the station is type 2 with the Dodo blueprint if the tech level is ≥ 10. In `TT18` the `DORND` of the failed jump enters with the carry of `CMP #9` (C = 1 if a key ≥ 9 is pressed; the port assumes no key).
- **Sounds that consume random numbers:** `SOEXPL` (explosions, death), `SOHISS` and `SOBOMB` call `DORND` once per click for the delay (Y times, 256 if Y = 0; 25 in `SOBOMB`) **if sound is on** (`DNOIZ` bit 7 = 0). The port now does too (`snd_dornd_hook`, set by `ships_hooks`). In `BOMBEFF` the carry `BOMBON` enters with is 1 in the space view and, outside it, the one `SOBOMB` leaves.
- **Radar colours:** on the Apple II `CYAN` and `MAG` equal `WHITE`: the "cyan" and "magenta" ships on the radar are white. The port shows them in cyan and magenta (a presentation decision, section 13).
- **`DOEXP` with 6 in byte 2 of the heap** (no ship: `4 * vertices + 6`) would make `EXL1` wrap Y around (256 copies); it does not occur with the game's blueprints and the test does not generate it.
- **Apple text mode:** the text views (all except space, the title and the charts) use the 40 × 24 text page; `NLIN4` then puts dashes (`NLI4`) under the characters of row 1. The QL has no text mode: `nlin4` always draws the `y = 19` line of graphics mode.
- **Stardust (round 17):** the `DORND`s of `KILL1`/`KILL6`/`KILL2`/`ST5` receive the carry of the comparison that sends them there (`CMP #120; BCS` → 1, `CMP #16; BCC` → 0, `BEQ` → 1); `PIXEL` returns with C = 1 if ZZ ≥ 80 or if the row is not a multiple of 8 (otherwise 0) and `PIXEL2` with C = 1 if the particle is outside; the first `DORND` of `nWq` carries the incoming carry, and `nWq` falls into `WPSHPS`. The port did not model those carries (22 % of the cases gave another cloud).
- **Charts (round 17):** the galactic chart's dots are `PIXEL` with ZZ = 255, i.e. **two dots** (the port put one); the local chart also has the `NLIN4` line at y = 19; `TT16`/`TT123` move the crosshair without sticking it to any system and do not move it if it would wrap (before, the port stuck it to the nearest system and limited it to the visible part of the local chart: see 13.1); in `TT23`, with row Y = 1 occupied, `Y - 2` = 255 reads `INWK - 1` = `SC+1` (never 0, the port treats it as occupied); `HME2` compares the name with the one `cpl` prints in the justified buffer: with `QQ17 = $C0` (the usual) it works, with `$80` it does not find system 0 (it comes out in capitals) and with 0 or `$40` none.
- **Tunnels (round 17):** in `HFL2`, each `SOHISS` enters with C = 0 (`CLC; ADC #8` or `CMP #160; BCC`); `TT110` does `LAUN` (two 256 `SOHISS` and the tunnel) **before** `RES2`/`SOS1`/`NWSPS` and then `HFS1` draws the same rings (with their sounds) again to erase them; the port now does it in that order (`tunnel_laun`, `space_launch`, `tunnel_draw`). In `LL164` the first `SBC #10` carries the incoming carry (with C = 0 the tones drop by 11 the first time).
- **Screen (round 17):** `TTX66` leaves `LSP = 0`, prints in the space view its name ("Front View" in Sentence Case, column 11, row 1) and, if there is a hyperspace countdown, the number at (1, 1); the graphic views carry `BOX` (blue line at y = 0, `HLOIN` from 0 to 255 plus the corners: dot 254 too); the blue borders `clearrow` paints (bytes 0 and 37 of each row) fall outside the game's 256 dots; `CLYNS` (jump token 21) did nothing in the port: it now clears rows 15 and 16 (y = 120..135) in the graphic views or writes 64 spaces from (1, 21) in the text ones.
- **Tools (round 17):** `PIX1` (Maths) falls into `PIXEL2`, `TT22` into `TT15`, `TT16` into `TT103`, `TT20` into `TT54`, `nWq` into `WPSHPS`, `CLYNS` into `clearrow` and `clearrow` into an `RTS` (`SCR1`): the following block has to come after. `BOX` has no header of its own (it is in the `TTX66K` block), `DTW2` is a byte of the code (without defining it, `STA DTW2` overwrote a stub) and the real `PIXEL` needs `TWOS3`, `SCTBL/H/H2` and `SCTBX1/2`. A hook set on the address of a real routine logs and lets it run.
- **Tools (round 16):** when a branch does not reach a label outside, `frag6502.build` adds a local `RTS`, **which does not imitate what is there**: `PL21` is `SEC; RTS` and with the local RTS `PLS6` returned C = 0 on overflow (the real routine had to be included). If the branch is far from the end, the local `RTS` must be placed right before the block (`TT48` in `DOEXP`). `SKIP n` is changed to `n` × `EQUB 0` (`BOMBTBX`); `EQUD %...` of `MASKT` is expanded; `DNOIZ` is a code label (without it it stayed as a stub, whose $60 byte has bit 7 = 0 = sound on). `tests/test_state` accepts the vectors file as an argument and now prints the port's value on failures.
- **Tools:** `frag6502.build` turns into stubs the `EQUW`s to outside routines (`JMTB` table); the `TT26` block also needs the `BELL` one (the `EQUB $2C` of `DA7` jumps to its `LDA #7`). `elitesrc.py` did not evaluate `INT(...)` (`Armlas` stayed undefined and the assembler turned it into a stub); fixed.


### 10.4 Golden rules
- **XOR drawing:** erase = draw the same thing again (same dots in the same order). If an area is cleared without telling the line heap (ships, sun, circle), those lines must be **forgotten**.
- **A truncated `u8` is not compared:** compute the sign first (10.1).
- **Carries as parameters:** model them explicitly; when in doubt, see which instruction consumes them (`ADC`/`SBC`/`ROL`/`BCS`).
- **Ship data** is extracted with a script, not by hand.
- **Always deliver** the tar + the three `.md` files at the end of each step, and check the tar in a clean directory.


## 11. Routine inventory

`tools/ported.txt` + `tools/inventory.py` generate `INVENTARIO.md` (528 routines of the source, grouped by the source's own category). **States:** `verificada` (compared with the 6502), `no-verificable` (ported, no comparable equivalent: not pending), `transcripcion` (with an own literal transcription), `sin-verificar` (ported, in `PENDIENTES.md`), `propia` (own equivalent in another form), `parcial` (reduced version; counts as pending), `no-necesaria`, empty = not ported.

**Summary as of 2026-10-18 (nineteenth round):** 528 routines = **426 ported** (269 verified against the 6502 + 7 not verifiable + 150 pending) + **102 not needed** + **0 not ported** (table by area at the start of `INVENTARIO.md`). **`no-verificable` state:** ported, but with nothing comparable in the original (Apple II text mode or keyboard, or the port's own screens); it does not count as pending and is not requested again.

**Criterion for "not needed":**
- *Apple II copy protection and boot:* `ENTRY`, `S%`, `DEEOR`, `DEEORS`, `G%`, `F%` (checksum and decryption of the code), `NMIpissoff`, `COLD`, `BEGIN`, `MUTILATE`/`UNMUTILATE` (anti-tampering encryption of the commander file; `save.c` has its own encryption), `SWAPPZERO`.
- *What the C compiler/runtime provides:* the **Utility routines** category (memory fills, page copies, loop delays, the `BRK` error handler), **Workspaces** (`ZP`, `XX3`, `K%`, `WP`, `Disk`, `UP`, `Option`: they are C variables) and **Tube** (`newosrdch`).
- *Apple II/BBC/C64 hardware:* hires screen tables (`SCTB*`, `cellocl`, `TWFL/TWFR`, `MASKT`), mode switching (`HGR`, `TEXT`), text-mode printing (`CHPR2`, `R5`, `RR5`), speaker (`CLICK`), key logger, Trumble sprites (VIC).
- *DOS 3.3 / RWTS:* catalogue, sectors, tracks, nibbles, disk arm (QDOS manages the disk).
- *Unused in the original* (`MUT3`, `LASNOISE2`, `beamcol`, `DKSANYKEY`, `KTRAN`).

## 13. Decisions and deviations from the original

- **Faithful port with own parts where the hardware demands it:** `LOIN` is the transcription (`loin_draw`, since round 16; before that it was Bresenham); `HLOIN` = `gfx_hloin` and `VLOIN` = `gfx_vloin` (same coverage as the original, solid colour instead of the Apple's bit patterns); the cyan and magenta radar colours (white on the Apple II) are kept; the charts are still own screens (`menu.c`: title in a blue bar, target information below, crosshair steps of 1 or 2 per frame), but what is drawn is the original; the panel uses the original bitmap converted to mode 8; the game save file is our own (ELQD, 94 bytes).
- **Line heaps** per slot (256 bytes) instead of the `SLSP` allocation; `K%` with 9 slots.
- **Station and planet:** the original's positions (`TT110` on launch, `SOLAR` on arrival, part 14 and `KS4`); `SOLAR` and `NWSPS` complete.
- **Test keys** `N`, `K` and `C` without computer: in the tests only (`flight_testkeys`).
- **`JSTGY`** starts at $FF (normal Y axis), like the IB disk; the source version leaves it at 0. **`K` (`JSTK`)** enables the QL CTL1 joystick (cursors and space, which were already the controls). The title shows the authors only with `PATG` (key `X` while paused), like the original.
- **Universe and market** come from Text Elite (verified against its oracle, not against the 6502); `uni_distance` follows the 6502.
- **Menu texts as C strings** (except the system data screen, which is the original's `TT25`); the mission screens and special descriptions use the **original token engine** (`detok.c`, with the source's tables). The normal description still comes from Text Elite.
- **Sound** translated from the 6502 loops to the QL's `BEEP`: approximate.
- **`TRADE_FAITHFUL 1`**: two arithmetic peculiarities of the original are reproduced.
- **Keys** distributed for the QL keyboard (section 8), different from the Apple II's.
