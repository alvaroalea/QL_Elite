# Decisions and deviations from the original

Moved from `CLAUDE.md` (section 9).

## 9.1 Criterion for "unnecessary routine":
- *Apple II copy protection and boot:* `ENTRY`, `S%`, `DEEOR`, `DEEORS`, `G%`, `F%` (checksum and decryption of the code), `NMIpissoff`, `COLD`, `BEGIN`, `MUTILATE`/`UNMUTILATE` (anti-tampering encryption of the commander file; `save.c` has its own encryption), `SWAPPZERO`.
- *What the C compiler/runtime provides:* the **Utility routines** category (memory fills, page copies, loop delays, the `BRK` error handler), **Workspaces** (`ZP`, `XX3`, `K%`, `WP`, `Disk`, `UP`, `Option`: they are C variables) and **Tube** (`newosrdch`).
- *Apple II/BBC/C64 hardware:* hires screen tables (`SCTB*`, `cellocl`, `TWFL/TWFR`, `MASKT`), mode switching (`HGR`, `TEXT`), text-mode printing (`CHPR2`, `R5`, `RR5`), speaker (`CLICK`), key logger, Trumble sprites (VIC).
- *DOS 3.3 / RWTS:* catalogue, sectors, tracks, nibbles, disk arm (QDOS manages the disk).
- *Unused in the original* (`MUT3`, `LASNOISE2`, `beamcol`, `DKSANYKEY`, `KTRAN`).

## 9.2 Decisions
- **Faithful port with own parts where the hardware demands it:** `LOIN` is the transcription (`loin_draw`, since round 16; before that it was Bresenham); `HLOIN` = `gfx_hloin` and `VLOIN` = `gfx_vloin` (same coverage as the original, solid colour instead of the Apple's bit patterns); the cyan and magenta radar colours (white on the Apple II) are kept; the charts are still own screens (`menu.c`: title in a blue bar, target information below, crosshair steps of 1 or 2 per frame), but what is drawn is the original; the panel uses the original bitmap converted to mode 8; the game save file is our own (ELQD, 94 bytes).
- **Line heaps** per slot (256 bytes) instead of the `SLSP` allocation; `K%` with 9 slots.
- **Station and planet:** the original's positions (`TT110` on launch, `SOLAR` on arrival, part 14 and `KS4`); `SOLAR` and `NWSPS` complete.
- **Test keys** `N`, `K` and `C` without computer: in the tests only (`flight_testkeys`).
- **`JSTGY`** starts at $FF (normal Y axis), like the IB disk; the source version leaves it at 0. **`K` (`JSTK`)** enables the QL CTL1 joystick (cursors and space, which were already the controls). The title shows the authors only with `PATG` (key `X` while paused), like the original.
- **Universe and market** come from Text Elite (verified against its oracle, not against the 6502); `uni_distance` follows the 6502.
- **Menu texts as C strings** (except the system data screen, which is the original's `TT25`); the mission screens and special descriptions use the **original token engine** (`detok.c`, with the source's tables). The normal description still comes from Text Elite.
- **Sound** translated from the 6502 loops to the QL's `BEEP`: approximate.
- **`TRADE_FAITHFUL 1`**: two arithmetic peculiarities of the original are reproduced.
- **Fixed flight step (10 FPS at most):** the whole simulation counts per frame (ships, AI, `MCNT`, energy, laser, `ALPHA`/`BETA` turning and speed) and the original ran at a few FPS, so on fast machines (Super Gold Card ~20 FPS, PC ~50) the game ran too fast and turning was abrupt. `flight_loop` waits until `FRAME_TICKS` (5 ticks of 50 Hz) since the previous frame (`flight.c`); with no clock (`plat_ticks() = 0`) or with a script it does not wait. With fewer than 10 FPS nothing changes. Scaling only the control input (`jstx`/`jsty`, `alpha`/`beta` by time) was discarded: the world still ran faster, and scaling the whole simulation breaks fidelity with the 6502. For another pace, change `FRAME_TICKS` (2 = 25 FPS).
- **Launch and hyperspace tunnel with its own pace:** the rings (`hfl1`, `sun.c`) are drawn back to back; on the real QL they were seen coming out one by one because of the slow drawing. `sun_pace_hook` (`ring_pace` in `flight.c`) waits `RING_TICKS` (2 ticks) per ring, and `wait_frames` waits by time (`TUNNEL_FRAMES` × `TUNNEL_TICKS`) and not by `in_poll` iterations. With no clock or with a script it does not wait.
- **Title and flight in mode 4 (option), station in mode 8 (2026-10-25):** **by default everything runs in mode 8**; in the pause options window (O key) the "512 mode" line (key **M**, variable `gfx_hires_opt`) switches title and flight to mode 4 and back to mode 8, immediately (panel and view are repainted; it is not saved with the game). With it on: mode 4 (512 × 256, black/red/green/white) gives lines and ellipses with double the horizontal resolution; the station stays in mode 8 for its colours. Mode 4 colours: **red is red, green is green and everything else white** (`gfx_ccode`); the **planet is green** (`ships.c`, formerly blue), the **compass ball** is white if it points to the planet and, if it points to the station, **yellow in mode 8 and red in mode 4** (`dash.c`, `compas`; green was tried and looked bad), the sun red, the X-shaped sight green and error messages red. Game dots are still 256 columns (2 physical dots wide) except lines and ellipses, which go at 512 (`docs/HARDWARE_QL.md`, Mode 4 screen): this way the text, panel, stars and rectangles code is the same and the aspect is preserved (the planet is still the game's `ry = 1.2 rx`; in physical dots, `rx` = 2 rx). If the panel's green/red/white is not liked: `dash_to_mode4` (dash.c) decides which colours of the `elite_dash` file are kept; an own file for mode 4 would replace that conversion. Mode changes are in `plat_mode` (main, `scr_title`, `game_run`, `flight_run`, `flight_screens`, option M of `pause_options`).
- **Keys** distributed for the QL keyboard (`docs/HARDWARE_QL.md`, Keyboard), different from the Apple II's.
