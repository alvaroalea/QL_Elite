# QL hardware

Moved from `CLAUDE.md` (section 7).

- **Memory:** screen at `$20000` (32 KB); target ≤ 640 KB.
- **Two screen modes (2026-10-25):** **by default everything runs in mode 8**; with the "512 mode" option (M key in the pause options, `gfx_hires_opt`) the **title and the flight view** run in **mode 4** (512 × 256, black, red, green and white) and **everything inside the station** (status, market, charts, equipment, disk...) stays in **mode 8**. `plat_mode(m4)` changes mode (`MT.DMODE` with D1 = **0** for mode 4 and 8 for mode 8, without touching the TV; it redefines the console full screen again and clears to black) and sets `gfx_m4`; `plat_init` starts in mode 8 (the demos) and `main` requests the option's mode (8 at start-up). Mode changes: `scr_title` (the option's mode), `game_run` after the title (mode 8), `flight_run` on launch (the option's mode) and on docking (mode 8; after death it stays at 4 because the title follows), `flight_screens` (text screens and charts from flight: mode 8 and back to the option's). `plat_shutdown` restores the mode the user started with. On the PC (`plat_host.c`) only the flag changes; `tools/ql2png.py capture.bin output.png 4` converts a mode 4 capture (1024 × 768, 4:3).
- **Screen (mode 4):** same memory (32 KB, 128 bytes per line, `$20000`); word = **8 dots**: even byte = green, odd byte = red (bit 7 = leftmost dot; white = both; no blue or *flash*). An 8 × 8 text cell is still 4 bytes wide, so `text.c`, the panel and the dot, span, column and rectangle routines are the same as in mode 8: **one game dot (x from 0 to 255) is 2 physical dots**, which fall exactly on the bit pairs (`s+1`, `s`) of mode 8; only the colour masks change. Internal colour code (`gfx_ccode`): in mode 4 only `C_RED` and `C_GREEN` keep their colour, black stays black and **any other colour is white**; bit 3 (mode 8's *flash*) is the second physical dot of green and bit 0 (blue) that of red (red = 3, green = 12, white = 15; `GFX_GM`/`GFX_RM` give the byte masks). The **lines** (`loin_draw`, `ql_line` → `ql_line4`) and the **ellipses of the planet and the tunnel rings** (`gfx_ellipse_xor`, `gfx_ell_spans`/`gfx_ell_update`, `ql_ellipse` with `hr` and `ql_ellrows4`) are drawn at the **512 dots** (physical x = 2 × game x; the horizontal semi-axis becomes 2 rx and the vertical one is still 1.2 rx, so the on-screen proportion is the usual one and the edges come out with double the resolution); the planet's span tables are 16-bit words. The panel background (`elite_dash`, in mode 8 format) is converted to mode 4 on loading (`dash_to_mode4`: pure red and green are kept, the rest is white) and both versions are stored.
- **Screen (mode 8):** word = 4 pixels; for pixel k (0 to 3, left to right) with `s = 2*(3-k)`: even byte with green in bit `s+1` and flash in bit `s`; odd byte with red in bit `s+1` and blue in bit `s`. 128 bytes per line. Colours: bit2 = green, bit1 = red, bit0 = blue (`C_*` in `platform.h`).
- **Graphics:** each word is 4 pixels; it is written directly to the screen (`$20000` on the QL, memory on the PC with the same format; `tools/ql2png.py` converts it to PNG).
- **Console (c68):** `plat_init` redefines the window as full screen, black border and no cursor (SD.WDEF, SD.CLEAR, SD.CURS) and registers `plat_shutdown` with `atexit`; the console keyboard queue is emptied with IO.FBYTE (timeout 0) at start-up, on every `plat_present()` and on exit (KEYROW does not consume key presses and SuperBASIC received them). `plat_exit()` cleans the console and removes the job with `MT.FRJOB` (`ql_trap1`) to avoid "Press a key to exit". `plat_wait_key()` (wait for a key press).
- **Keyboard:** `KEYROW` through the IPC (command 9), one call per row (0–7); 8-byte `MT.IPCOM` block `9,1,0,0,0,0,<row>,2`, reply in D1.B. **Each row is a slow call**: `key_ctx_menu()` reads rows 1 and 7 always and the rest rotating (3 reads per frame); `key_ctx_flight()` reads rows 1, 3 and 4 always and 0, 2, 5, 6 and 7 rotating (4 reads). A key in a rotating row is detected within at most 5 (flight) or 6 (menus) frames. `KEYROW` reads the physical keyboard even if another window has the focus; three keys in a matrix rectangle give a ghost.
- **Clock and pace:** `plat_ticks()` gives 50 Hz ticks (on the QL, `ql_ticks()`; 0 if there is no clock task). Flight is limited to 10 FPS (`FRAME_TICKS` = 5) and the tunnel rings go at `RING_TICKS` = 2 ticks each; see `docs/DECISIONES.md`. On a real QL (2-6 FPS) it never waits.
- **Joystick:** on the QL they are keys: CTL1 = cursors and space (row 1), CTL2 = F1–F5 (row 0). Provisional UK layout of the menus; CTRL+Left gives character 8.
- **Sound:** `BEEP` through the IPC (`MT.IPCOM`), command 10 with 8 parameter bytes (`$0000AAAA`), 15-byte block with interval and duration **low byte first** and **reply 1 (none)**; `BEEP OFF` = command 11 (also with reply 1). **If a reply that the 8049 does not send is requested, the link gets out of sync and the QL hangs**. A new `BEEP` cancels the previous one; do not sound while a job is being loaded or unloaded. Pitch = 0.022457·cycles − 9.6 (frequency = 22917 / (2·(pitch + 9.6)) Hz); duration and interval in steps of 43.64 µs (the 8049 gives 22,917 per second; the manual's 72 µs is wrong). All the original's effects are translated from the 6502 loops, with priorities.
- **Trap #3:** `ql_trap3(d0,d1,d2,d3,a0,a1)` in `ql_ipc.asm` loads registers, executes `trap #3` and returns D0 (0 ok, negative QDOS error). Codes: IO.FBYTE=1, SD.WDEF=$0D, SD.CURE=$0E, SD.CURS=$0F, SD.CLEAR=$20; from `qdos.h` only `fgetchid` and `mt_dmode` are used.
- **Disk:** `elite.img` image with `make elite.img` (`docs/HERRAMIENTAS.md` 3.5); boot through the `boot` file. QDOS files from C (`fopen`/`fwrite`): `flp1_`, `flp2_`, `mdv1_`, `mdv2_` (or a directory on the PC). Data go as `<drive>elite_dash` (panel) and `<drive>elite_<name>` (saved games). **Game drive** (`find_drive` in main.c): the optional argument of `EXEC_W dev$&"elite";dev$` (Toolkit II/SMSQ/E syntax: without TK2 it gives `bad parameter`, which is why `boot` does not pass it; the c68 runtime gives it in `argv[1]`; `_` is appended if missing) or, with no argument, the first one where `elite_dash` opens: `DATA_USE`, `PROG_USE` (`plat_default_dir`: `getenv`; c68's `getcdd` reads `SPL_USE`), `flp1_`, `flp2_`, `win1_`, `mdv1_`, `mdv2_`; if it does not appear, `flp1_`. **Own `_envsetup` (plat_ql.c, 2026-10-25):** the c68 4.24f runtime's one (called by `Cinit` before `main`) copies the TK2 directories (pointers to a QDOS string at `SV+$AC`/`$B0`/`$B4` → `PROG_USE`/`DATA_USE`/`SPL_USE`) without checking anything into a 50-byte stack buffer. Without TK2 the pointers are 0 and it reads the length at ROM address 0: JS = 3 (harmless garbage), **Minerva = $4C02 → copies 19,458 bytes, wrecks the stack and hangs before `main`** (blank screen). The replacement does the same but demands an even pointer in RAM and a length of 1..49. The game silences sound before touching the disk.
- **Performance:** the 68008 is slow and the bus is 8 bits wide.
